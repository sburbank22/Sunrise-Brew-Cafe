AI Development Transcript – Sunrise Brew Cafe Project

  ---
  Prompt:
  I have a plain HTML, CSS, and JavaScript website for a coffee shop called Sunrise Brew Café. I
  want to add an AI-powered menu description generator. When a staff member types a menu item name,
  it should use AI to generate a short, appealing description for it. How should I approach this?

  Response:
  Great idea for a café site. The cleanest approach is a Netlify serverless function that calls the
  Anthropic API on the backend — that way your API key stays private and never appears in your
  frontend JavaScript.

  Here's the plan:
  1. Create netlify/functions/generate-description.js that accepts a menu item name and returns an
  AI-generated description
  2. Add a small UI section to your menu.html with an input, button, and output area
  3. Your frontend fetches /.netlify/functions/generate-description with the item name

  Let's start with the Netlify function...

  ---
  Prompt:
  Okay, here's what I have so far for the function. I'm calling anthropic.messages.create() with
  claude-3-haiku-20240307. What do I set for the prompt?

  Response:
  Use a system prompt that gives the model its role, and a user message with the item name.
  Something like:

  const response = await anthropic.messages.create({
    model: "claude-3-haiku-20240307",
    max_tokens: 150,
    system: "You write short, warm, appetizing menu descriptions for a cozy artisan café. Keep
  descriptions to 2-3 sentences.",
    messages: [{ role: "user", content: `Write a menu description for: ${itemName}` }]
  });

  Then return response.content[0].text as your JSON response body.

  ---
  Prompt:
  How do I set up the API key? I don't want to hardcode it.

  Response:
  Use an environment variable. In your function, reference it as:

  const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

  In Netlify, go to Site configuration → Environment variables and add:
  - Key: ANTHROPIC_API_KEY
  - Value: your API key from console.anthropic.com

  For local dev, create a .env file in your project root (and add it to .gitignore) with:
  ANTHROPIC_API_KEY=sk-ant-...

  ---
  Prompt:
  I deployed it but when I click the generate button I get an error in the console. The Netlify
  function log says:
  {"error":{"type":"error","error":{"type":"authentication_error","message":"credit balance is too
  low"}}}

  Response:
  That error means the Anthropic account tied to that API key has no credits — it's a billing issue,
   not a code issue. Your function is working correctly.

  A few things to check:
  1. Log into console.anthropic.com and confirm the account has a credit balance under Billing
  2. Make sure the API key you pasted into Netlify actually belongs to the account that has credits
  — it's easy to accidentally generate a key on a different account if you have multiple
  3. If the balance is zero, add credits under Billing → Buy credits

  ---
  Prompt:
  I think I see the problem — I have two Anthropic accounts and I added credits to one but generated
   the API key from the other. I created a new key from the correct account. Should I just update
  the environment variable in Netlify?

  Response:
  Exactly right. Go to Site configuration → Environment variables, find ANTHROPIC_API_KEY, and
  update the value to your new key. Then trigger a redeploy (or Netlify will pick it up on the next
  deploy automatically).

  Once that's done, test the function again — you should see a description come back instead of the
  auth error.

  ---
  Prompt:
  It's working now! The descriptions look great. I want to add a second feature — a "coffee quote of
   the day" that shows a random coffee-related quote on the homepage. I found a free quotes API I
  want to use. Can I just fetch it directly from my JavaScript?

  Response:
  It depends on whether that API supports CORS for browser requests. Many free public APIs do not
  send the right Access-Control-Allow-Origin headers, which means the browser will block the request
   even if it works fine in curl or Postman.

  Try it directly first — if you see a CORS error in the browser console, you'll need to proxy it
  through a Netlify function, the same pattern you used for the AI feature.

  ---
  Prompt:
  I tried fetching it directly and I'm getting: Access to fetch at 'https://[quotes-api]' from
  origin 'https://my-site.netlify.app' has been blocked by CORS policy: No
  'Access-Control-Allow-Origin' header is present on the requested resource.

  Response:
  That confirms it — CORS is blocked. The fix is a thin Netlify proxy function. Create
  netlify/functions/get-quote.js:

  exports.handler = async () => {
    const res = await fetch("https://[quotes-api-url]");
    const data = await res.json();
    return {
      statusCode: 200,
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(data)
    };
  };

  Then in your frontend, fetch /.netlify/functions/get-quote instead of the external URL directly.
  Since the request now originates from your own Netlify domain (server-side), CORS doesn't apply.

  ---
  Prompt:
  That worked perfectly. The quote shows up on the homepage now. So to summarize, all my external
  API calls go through Netlify functions?

  Response:
  Exactly — that's the right pattern for a static site. Netlify functions act as a secure middleware
   layer:

  - API keys stay private — never exposed in client-side JavaScript
  - CORS is bypassed — server-to-server calls aren't subject to browser CORS restrictions
  - One consistent pattern — your frontend always fetches /.netlify/functions/your-function,
  regardless of what's happening behind the scenes

  Your site now has two working serverless functions: one for AI-generated menu descriptions and one
   for the coffee quote feature. Both follow the same architecture.
